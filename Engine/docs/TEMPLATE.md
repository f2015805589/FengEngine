# 模块文档写作模板

> 本模板用于撰写 Engine/docs 下的模块文档：将一级标题替换为实际模块名，正文按各章节的写作说明填充，并在完成后删除本提示。所有章节均使用 `##` 二级标题，保持 8 个章节的结构完整，便于读者快速定位。

## 概述

- 用 2-3 段说明模块的职责与定位：解决什么问题、处于引擎渲染流程的哪个环节。
- 说明与上下游模块的关系（谁调用它、它依赖谁），让读者在一分钟内理解模块全貌。
- 可选：列出核心特性、适用场景与关键性能指标。

## 核心文件清单

- 以表格列出模块涉及的关键源文件：文件路径（相对 `Engine/` 根目录，用反引号包裹）、职责说明。
- 文件名保持 ASCII（如 `RenderPipeline.h` / `RenderPipeline.cpp`），避免中文文件名带来的跨平台问题。
- 按头文件、实现文件、资源文件（shader、material 等）分组，便于检索。

## 架构与数据流

- 说明模块内部结构：核心类及职责、类之间的依赖关系、生命周期（创建、初始化、每帧更新、销毁）。
- 描述数据流：输入数据来源、处理过程、输出数据去向；建议用 ASCII 流程图或 mermaid 图辅助说明。
- 涉及 GPU 资源（Buffer、Texture、PSO、Root Signature）时，说明创建时机、绑定方式与释放策略。

## 关键实现要点

- 总结核心算法、渲染技巧与性能优化点，每个要点用 1-2 句说明“为什么这么做”，避免只罗列代码。
- 记录实现过程中踩过的坑与规避方法，供后续维护者参考。
- 要点按重要性排序，可附简短代码片段或伪代码。

## 对外接口

- 列出模块对外暴露的类、函数与 API，注明所在文件与调用方式（直接调用、事件回调、资源引用等）。
- 说明关键参数含义、返回值与典型调用示例（伪代码或短代码块）。
- 标注接口的线程约束：哪些只能在主线程调用，哪些可跨线程。

## 配置与调参

- 列出可通过配置文件、编辑器面板或代码修改的参数，说明取值范围、默认值与效果。
- 用表格组织：参数名 / 配置位置 / 默认值 / 说明。
- 说明参数之间的耦合关系与推荐取值组合，避免盲目调参。

## 已知限制与 TODO

- 记录当前已知问题、未实现功能与计划中的改进，标注优先级或关联任务。
- 说明限制产生的原因与可能的解决方向，避免重复排查。
- 已解决的问题及时归档或删除，保持清单精简。

## 维护注意事项

- 提醒修改该模块时的注意事项：依赖关系、资源释放、线程安全、平台差异（Windows、D3D12 特性级别）等。
- 注明修改后建议的验证方式：运行哪个示例、观察哪些渲染结果或性能指标。
- 记录常用调试手段（RenderDoc、ImGui 调试面板、日志开关），降低后续维护成本。
